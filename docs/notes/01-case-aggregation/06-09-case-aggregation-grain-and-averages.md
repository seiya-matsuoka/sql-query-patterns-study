# CASE による集計の粒度と平均の分母

行ごとの分類を集計へつなぎ、条件付き平均が何個の値を使うかを整理する。
SQL と詳細な処理説明は、次の順に読む。

1. [金額帯別の集計](../../../sql/01-case-aggregation/06-amount-band-summary.sql)：同じ分類キーを持つ注文をまとめる。
2. [複数の条件別指標](../../../sql/01-case-aggregation/07-conditional-order-metrics.sql)：顧客ごとの件数・合計・平均を並べる。
3. [平均へ渡す値と分母](../../../sql/01-case-aggregation/08-conditional-average-denominators.sql)：ELSE の有無で分母が変わる理由を追う。
4. [空入力の条件付き集約](../../../sql/01-case-aggregation/09-empty-conditional-aggregates.sql)：集計結果の 1 行と 0 行を区別する。

## 分類した明細から集計行へ

`06-amount-band-summary.sql` の元の入力は、1 行 1 注文の 10 行である。
CASE で求める分類キーは、1 が少額、2 が中額、3 が高額、NULL が金額不明を表す。
派生表で分類する段階では 10 行を保ち、外側の `GROUP BY amount_band_no` で 4 行へまとめる。
結果の 1 行は 1 注文ではなく、同じ分類キーを持つ注文全体である。

次の値は、入力の注文を分類し、判明金額を数えて足すことで導ける。
平均の分母は判明金額の個数であり、金額が不明の注文を 0 円として数えない。

| 分類キー | 対象の注文 ID      | 全件数 | 判明件数 | 判明金額の合計 | 平均の導出            |
| -------- | ------------------ | ------ | -------- | -------------- | --------------------- |
| 1        | 101、102           | 2      | 2        | 99.99          | 99.99 / 2 = 49.995    |
| 2        | 103、104、105、109 | 4      | 4        | 800.00         | 800.00 / 4 = 200      |
| 3        | 106、107           | 2      | 2        | 1000.01        | 1000.01 / 2 = 500.005 |
| NULL     | 108、110           | 2      | 0        | NULL           | 対象値がなく NULL     |

分類キーが NULL の 2 注文も、一つのグループにまとまる。
`NULL = NULL` が真になるという説明ではなく、GROUP BY では NULL キーを同じグループとして扱うという規則である。
金額 NULL という入力行があることと、入力行がないことは異なる。

直接の CASE 式を `SELECT` と `GROUP BY` に書く方法と、派生表で計算したキーを外側で使う方法は、同じ入力・分類規則・金額式・重複数・集約単位なら同じ結果になる。
同額の別注文も保持し、NULL の分類キーも保持する。
表示順は両方とも最終 `ORDER BY amount_band_no NULLS LAST` で揃える。
派生表の段階で重複除去や入力の絞り込みを追加すると、この比較の前提が変わる。
派生表を使うことだけで、物理的な一時保存や高速化が保証されるわけではない。

## 条件別件数・合計・平均の対象

`07-conditional-order-metrics.sql` は別の専用入力を使い、1 行を 1 注文から 1 顧客の集計へ変える。
支払状態は `paid` と `unpaid` だけとし、金額 NULL と支払状態を別の情報として扱う。
顧客 1 の同額の未払い 2 件は別注文であり、両方を件数・合計・平均へ含める。

| 顧客 | 全注文数 | 支払済みの入力金額 | 支払済み件数 | 判明件数 | 判明合計 | 判明平均 | 未払いの入力金額 | 未払い件数 | 判明合計 | 判明平均 |
| ---- | -------- | ------------------ | ------------ | -------- | -------- | -------- | ---------------- | ---------- | -------- | -------- |
| 1    | 5        | 100.00、0.00、NULL | 3            | 2        | 100.00   | 50       | 60.00、60.00     | 2          | 120.00   | 60       |
| 2    | 1        | 該当なし           | 0            | 0        | NULL     | NULL     | 80.00            | 1          | 80.00    | 80       |
| 3    | 1        | NULL               | 1            | 0        | NULL     | NULL     | 該当なし         | 0          | NULL     | NULL     |
| 4    | 1        | 0.00               | 1            | 1        | 0.00     | 0        | 該当なし         | 0          | NULL     | NULL     |
| 5    | 2        | NULL               | 1            | 0        | NULL     | NULL     | 40.00            | 1          | 40.00    | 40       |

未払い金額はこの入力ではすべて非 NULL なので、未払いの判明件数は未払い件数と等しい。
一般に `COUNT(amount)` と `COUNT(*)` が等しいという意味ではない。
顧客 6 は入力に注文がないため、顧客別の集計行もない。

同じ入力・条件・金額式・重複数・グループを使うとき、次の組み合わせは同等になる。
条件が真の行を使い、CASE の ELSE を省略する点が前提である。

| CASE の記述                          | FILTER の記述                    | 数えるもの・集約するもの                    |
| ------------------------------------ | -------------------------------- | ------------------------------------------- |
| `COUNT(CASE WHEN p THEN 1 END)`      | `COUNT(*) FILTER (WHERE p)`      | 条件に該当した行。金額 NULL も含む          |
| `COUNT(CASE WHEN p THEN amount END)` | `COUNT(amount) FILTER (WHERE p)` | 条件に該当し、金額も非 NULL の行            |
| `SUM(CASE WHEN p THEN amount END)`   | `SUM(amount) FILTER (WHERE p)`   | 条件に該当する非 NULL 金額の合計            |
| `AVG(CASE WHEN p THEN amount END)`   | `AVG(amount) FILTER (WHERE p)`   | 条件に該当する非 NULL 金額の合計 / その個数 |

上表の `p` は条件を表す説明用の記号であり、教材では `status = 'paid'` または `status = 'unpaid'` を書く。
FILTER は付けた集約だけを絞り、他の集約や GROUP BY の入力は除去しない。
問い合わせ全体に `WHERE status = 'paid'` を加えると、未払い 4 行がすべての集約の前に除かれる。
その比較では顧客 2 のグループが消え、顧客 1 と 5 の `order_count` はそれぞれ 3 と 1 になる。
残る顧客の支払済み指標は同じだが、未払いの件数は 0、合計・平均は NULL になり、元の全注文の報告とは異なる。

## ELSE 0 はどの平均を作るか

顧客 1 の金額を、AVG へ渡す前の段階で比較する。
`conditional-average-input-values` の明細列が、次の対応を示す。

| 注文 ID | 状態   | 元金額 | ELSE 省略の値 | ELSE 0.00 の値 |
| ------- | ------ | ------ | ------------- | -------------- |
| 101     | paid   | 100.00 | 100.00        | 100.00         |
| 102     | paid   | 0.00   | 0.00          | 0.00           |
| 103     | paid   | NULL   | NULL          | NULL           |
| 104     | unpaid | 60.00  | NULL          | 0.00           |
| 105     | unpaid | 60.00  | NULL          | 0.00           |

ELSE 省略の分母は 2 個で、平均は 100.00 / 2 = 50 になる。
ELSE 0.00 の分母は 4 個で、平均は 100.00 / 4 = 25 になる。
ID 103 は THEN に入って NULL を返すため、ELSE があっても 0 にはならない。

| 顧客 | ELSE 省略の分母 | CASE と FILTER の平均 | ELSE 0.00 の分母 | ELSE 0.00 の平均 | 違いの理由                                  |
| ---- | --------------- | --------------------- | ---------------- | ---------------- | ------------------------------------------- |
| 1    | 2               | 50                    | 4                | 25               | 未払い 2 行が分母に加わる                   |
| 2    | 0               | NULL                  | 1                | 0                | 未払い行から 0 を作る                       |
| 3    | 0               | NULL                  | 0                | NULL             | 金額不明の支払済みだけで ELSE を通らない    |
| 4    | 1               | 0                     | 1                | 0                | 実際の金額 0 を平均する                     |
| 5    | 0               | NULL                  | 1                | 0                | 支払済みの NULL は残り、未払いだけ 0 になる |

ELSE 0.00 の分母は、金額が判明した支払済みの件数と、条件が真でない行の件数の和である。
金額 NULL の支払済み注文があると、全注文件数とも一致しない。
支払済み判明金額だけの平均が必要なら ELSE 省略または FILTER を使う。
ELSE 0.00 は異なる対象の平均を定義する比較であり、一律に同等な書き換えとは扱わない。

## 該当なし・全値 NULL・実額 0・空入力

| 状況                                            | 結果行 | 支払済み件数 | 平均の対象値の個数 | ELSE 省略の平均 | ELSE 0.00 の平均 |
| ----------------------------------------------- | ------ | ------------ | ------------------ | --------------- | ---------------- |
| 未払いのみの顧客 2 を、全注文から顧客別集約     | 1 行   | 0            | 0                  | NULL            | 0                |
| 金額不明の支払済みのみの顧客 3 を顧客別集約     | 1 行   | 1            | 0                  | NULL            | NULL             |
| 実額 0 の支払済みのみの顧客 4 を顧客別集約      | 1 行   | 1            | 1                  | 0               | 0                |
| WHERE 通過後が空で、GROUP BY のない全体集約     | 1 行   | 0            | 0                  | NULL            | NULL             |
| WHERE 通過後が空で、customer_id ごとの GROUP BY | 0 行   | 行なし       | 行なし             | 行なし          | 行なし           |

表の「平均の対象値の個数」は、ELSE 省略または FILTER の平均に対応する。
空入力では CASE を評価する行がなく、ELSE 0.00 も 0 を生成しない。
グループ分けした空入力の期待 CSV はヘッダーだけを持つ。
件数 0 と平均 NULL を持つ 1 行の CSV とは、行数を含めて区別する。

## 期待 CSV と DBMS ごとの表示

期待値は上の入力・分類・件数・加算・分母から導出し、実行結果から自動更新しない。
教材では AVG の結果を丸めたり、NULL を 0 に置換したりしない。
金額の入力は DECIMAL を使い、PostgreSQL の AVG は numeric の結果を返す。
CSV に含まれる末尾の小数桁はこの環境の numeric の出力形式であり、あらゆる DBMS の表示形式を定めるものではない。
NULL は既存の検証方式に従って `<NULL>` と表示する。
書き方による性能は未評価とする。

集約の非 NULL 値・空入力の扱いは [PostgreSQL 18 の集約関数](https://www.postgresql.org/docs/18/functions-aggregate.html)、FILTER の対象は [集約式](https://www.postgresql.org/docs/18/sql-expressions.html#SYNTAX-AGGREGATES) を参照する。
グループの粒度と WHERE との関係は [表式の GROUP BY](https://www.postgresql.org/docs/18/queries-table-expressions.html#QUERIES-GROUP)、ELSE 省略は [CASE](https://www.postgresql.org/docs/18/functions-conditional.html#FUNCTIONS-CASE) を参照する。
